1. 프로젝트 개요
--------------------------------------------------------------------------
- Docker 공식 샘플 "getting-started-todo-app"을 기반으로, 원래 Node.js(Express)
  백엔드를 Python FastAPI + Uvicorn(비동기) 백엔드로 변환한 Todo 리스트 웹 앱.
- 프론트엔드: React 19 + Vite 6 + React-Bootstrap (SPA)
- 백엔드:     FastAPI (Python 3.12), REST API 제공 + 빌드된 SPA 정적 파일 서빙
- 데이터베이스: SQLite(기본, 로컬) 또는 MySQL 9.3(환경변수 지정 시, Docker Compose 개발/운영환경, GKE)
- 실행 환경: Docker Compose 개발 (Traefik 리버스 프록시 + backend + client + MySQL + phpMyAdmin)
             Docker Compose 운영 (compose-prod.yaml: Traefik + 단일 backend 이미지 + MySQL)
             GKE 운영 (Helm 차트 helm/todo-app: Ingress/LoadBalancer + backend + MySQL StatefulSet)
             또는 Windows 로컬 직접 실행
- 프로젝트 관리: Spec Kit 방식. 기능 명세(specs/001-todo-list-app/)와 헌법(.specify/)을
  이 저장소에 두고, 앱 코드도 같은 저장소 루트에 둔다.

3. 기능 요구사항 (Functional Requirements)
--------------------------------------------------------------------------
FR-001  인사말 표시: 화면 상단에 서버에서 받은 인사말("Hello world!")을 표시한다.
FR-002  할 일 목록 조회: 저장된 모든 항목을 추가된 순서(오래된 것부터)로 표시한다.
        완료/미완료 전환은 항목의 위치를 바꾸지 않는다.
        항목이 없으면 "No items yet! Add one above!"를 표시한다.
        목록 로드에 실패하면 빈 목록 문구 대신 오류와 "Try again" 버튼을 표시한다.
FR-003  할 일 추가: 이름을 입력하여 새 항목을 추가한다.
        - 공백을 제외한 이름이 1자 이상이어야 한다. 공백만 있는 이름은 비어 있는 것으로 본다.
        - 이름 길이 255자 초과는 서버가 422로 거부하고, "Names must be 255 characters or fewer."를 표시한다.
        - 추가에 실패하면 입력한 이름을 입력창에 남기고 메시지를 표시한다.
        - 추가에 성공하면 입력창을 비운다.
        - ID는 서버에서 UUID v4로 생성, completed 기본값 false. 응답에 순서 정보는 없다.
FR-004  완료 상태 토글: 체크박스 아이콘 클릭으로 completed 값을 반전한다.
        이름은 보내지 않는다(이름 변경과 충돌하지 않도록).
FR-005  할 일 수정: name/completed 중 전달된 필드만 부분 수정한다.
        존재하지 않는 ID이면 404 "Item not found"를 반환한다.
FR-006  할 일 삭제: 휴지통 아이콘 클릭으로 항목을 삭제한다.
        존재하지 않는 ID를 삭제하려 하면 404 "Item not found"를 반환하고, 사용자에게 알린다.
FR-007  데이터 영속성: 서버/컨테이너 재시작 후에도 데이터와 순서, 완료 상태가 유지된다
        (SQLite 파일, Compose MySQL 볼륨 todo-mysql-data, GKE MySQL StatefulSet의 PVC).
FR-008  이름 변경: 항목의 편집 버튼으로 대화상자를 열어 이름을 바꾼다.
        - 이름 텍스트를 클릭해도 대화상자는 열리지 않는다.
        - 저장 전 입력값은 공백을 제거한 뒤 검사한다. 빈 이름이나 255자 초과 이름이면 저장을 막는다.
        - 취소하면 항목은 바뀌지 않는다. 이름을 바꿔도 위치와 완료 상태는 유지된다.
FR-009  동기화 알림: 다른 탭이나 사용자가 이미 삭제한 항목을 바꾸거나 지우려 하면
        "This item no longer exists" 안내를 보여 주고 목록을 다시 불러온다.
FR-010  접근성 기준 (헌법 III): 모든 조작은 키보드로 할 수 있어야 하고, 아이콘 버튼은
        동작과 항목 이름을 포함한 접근 가능한 이름을 가져야 한다.


4. REST API 명세
--------------------------------------------------------------------------
 (모든 엔드포인트는 /api 접두사 버전과, 스키마에 숨겨진 접두사 없는 별칭을 함께 제공)

 메서드  경로                    요청 본문                          응답
 ------  ----------------------  ---------------------------------  -----------------------------
 GET     /api/greeting           -                                  200 {"greeting": "Hello world!"}
 GET     /api/items              -                                  200 [Item, ...] (추가 순서)
 POST    /api/items              {"name": str}                      200 Item / 422 검증 실패
                                 (공백 제거 후 1~255자)
 PUT     /api/items/{item_id}    {"name"?: str, "completed"?: bool} 200 Item / 404 없음 / 422 검증 실패
 DELETE  /api/items/{item_id}    -                                  200 (본문 없음) / 404 없음
 GET     /docs                   FastAPI 자동 생성 Swagger UI
 GET     /  (그 외 경로)         backend/src/static 의 React SPA (디렉터리 존재 시)

 Item 모델: { "id": str(UUID), "name": str, "completed": bool }
 (created_seq는 저장 전용이며 응답에 포함하지 않는다.)


5. 데이터 저장소 요구사항
--------------------------------------------------------------------------
- 테이블: todo_items (id VARCHAR(36), name VARCHAR(255), completed BOOLEAN, created_seq)
  - created_seq: 추가 순서를 정하는 정수. 새 항목은 최댓값 + 1을 받는다.
  - 앱 시작 시 CREATE TABLE IF NOT EXISTS 로 자동 생성하고, created_seq가 없으면 추가한다.
    - SQLite: 기존 행은 rowid 값으로 채운다.
    - MySQL: BIGINT AUTO_INCREMENT UNIQUE 컬럼을 추가한다.
      MySQL은 키가 없는 테이블에서 이 컬럼을 PRIMARY KEY로 만든다(확인됨).
  - 두 번째 시작에서도 값은 바뀌지 않는다.
- 저장소 선택 규칙:
  - MYSQL_HOST 또는 MYSQL_HOST_FILE 환경변수가 있으면 MySQL, 없으면 SQLite.
- SQLite
  - 경로: SQLITE_DB_LOCATION (기본 /etc/todos/todo.db, 상위 폴더 자동 생성)
  - Windows 로컬 실행 시 기본 경로 대신 SQLITE_DB_LOCATION 지정 권장.
- MySQL
  - 접속 정보: MYSQL_HOST / MYSQL_USER / MYSQL_PASSWORD / MYSQL_DB
    (각각 *_FILE 변수로 Docker secret 파일 경로 지정 가능)
  - 기본값: localhost / root / "" / todos, 포트 3306 고정, utf8mb4
  - 커넥션 풀 min 1 / max 5, autocommit
  - DB 준비 대기: 1초 간격 최대 30회 재시도


6. 비기능 요구사항 (Non-Functional Requirements)
--------------------------------------------------------------------------
NFR-01 비동기 처리: FastAPI + aiosqlite/aiomysql 로 모든 DB I/O를 async 처리.
NFR-02 CORS: 개발 편의를 위해 모든 Origin/메서드/헤더 허용 (운영 시 제한 필요, 아직 미정).
NFR-03 Windows 호환: Windows 레지스트리의 잘못된 MIME 타입 문제를 막기 위해
       .js/.mjs/.css/.svg/.json/.ico MIME 타입을 코드에서 강제 등록.
NFR-04 테스트: pytest + pytest-asyncio + httpx(ASGITransport)로 라우트/영속성 테스트.
       MySQL 테스트는 실제 서버 없이 가짜 커넥션 풀로 수행한다(헌법 II).
       Docker 'test' 스테이지에서 테스트가 통과해야 'final' 이미지가 빌드됨.
NFR-05 개발 생산성: Compose Watch로 소스 변경 시 컨테이너에 자동 동기화,
       uvicorn --reload / Vite HMR로 자동 재시작.
NFR-06 단일 배포: final 이미지는 React 빌드 결과를 FastAPI가 직접 서빙(포트 3000)하는
       단일 컨테이너로 구성.
NFR-07 성능: 항목 100개 목록이 페이지를 연 뒤 2초 이내에 모두 표시되어야 한다 (SC-006).
       서버 측 측정값(SQLite, 100개 목록 조회)은 중앙값 약 1.6 ms였다.
       브라우저 표시 시간은 아직 측정하지 않았다.

8. 실행 환경 구성
--------------------------------------------------------------------------
8-1. Docker Compose 개발 환경 (권장)
   docker compose watch      (또는 docker compose up --build)
   - http://localhost          → client (Vite, 5173)
   - http://localhost/api/*    → backend (FastAPI, 3000)
   - http://db.localhost       → phpMyAdmin
   - Traefik이 80 포트에서 Host/PathPrefix 라벨 규칙으로 라우팅.
   - backend는 mysql 헬스체크(mysqladmin ping) 통과 후 시작.

8-2. 운영(단일) 이미지
   docker build -t todo-app .            (target 기본값 = final)
   docker run -p 3000:3000 todo-app      → http://localhost:3000
   - 이 경우 MySQL 환경변수가 없으므로 SQLite 사용.

8-3. Windows 로컬 직접 실행
   (백엔드)  cd backend
             python -m venv .venv  →  .venv\Scripts\activate
             pip install -r requirements.txt
             python main.py                   → http://localhost:3000
   (프론트)  cd client
             npm install
             npm run dev                      → http://localhost:5173 (/api 는 3000으로 프록시)
             npm run build                    → dist 생성 후 backend/src/static 으로 복사
                                                (복사 전에 기존 static 폴더 내용을 지운다)
   (테스트)  cd backend  →  pytest
   (lint)    cd client   →  npm run lint
             참고: 드라이브 루트(d:\)에 eslint.config.js가 있으면 ESLint 8이 flat 모드로 전환되어
             lint가 실패한다. 그 파일을 지우거나 ESLINT_USE_FLAT_CONFIG=false 로 실행한다.

8-4. 운영 Compose (compose-prod.yaml)
   cp .env.example .env   # 비밀번호 값 입력 (.env는 git 무시)
   docker compose -f compose-prod.yaml up -d --build
   - Traefik이 80 포트만 공개한다. backend 는 traefik.enable=true 라벨이 붙은 서비스만 노출한다.
   - 백엔드는 MySQL 전용 사용자(MYSQL_APP_USER)로 접속한다(root 아님).
   - MySQL 포트는 호스트에 공개하지 않는다.

8-5. GKE 배포 (Helm 차트 helm/todo-app)
   helm upgrade --install <release> ./helm/todo-app -n todo --create-namespace \
     --set secrets.mysqlRootPassword=<...> --set secrets.mysqlAppPassword=<...>
   - 구성: backend Deployment(포트 3000, 기본 레플리카 2) + backend Service
     (backend.service.type 기본값 LoadBalancer, ClusterIP로 변경 가능)
     + mysql StatefulSet(mysql:9.3, PVC 10Gi) + Secret + Ingress(ingressClassName gce, 선택).
   - compose-prod.yaml 대응: Traefik → GKE Ingress/LoadBalancer, depends_on(healthy) → wait-for-mysql init container.
   - 백엔드 DB 연결은 앱의 재시도 로직(최대 30초)과 init container가 함께 보장한다.
   - 비밀번호는 차트에 저장하지 않는다. --set 또는 secrets.existingSecret 로만 전달한다.
   - 설치·고정 IP·관리형 인증서·제거 절차: helm/todo-app/README.md
   - 주의: LoadBalancer 타입은 외부 공인 IP와 비용이 생긴다. Ingress와 함께 쓰면 진입점이 둘이 된다.
